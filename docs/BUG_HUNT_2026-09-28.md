# Bug hunt — 2026-09-28

Base commit: `5c903492fbe4388677c0c0b68bd3ab1009e858fe`.

The original 15 backend tests, reference calculator, frontend build, and frontend dependency audit passed. Additional API, arithmetic, ingestion, and browser checks reproduced defects outside that coverage.

| Area | Reproduced behavior | Correction |
| --- | --- | --- |
| Request validation | Empty histories and invalid loan terms crashed; negative debt and infinite income could improve decisions. | Validate history, debt, principal, rate, term, income, and finite numeric inputs before calculation. |
| Ownership | Two 100% guarantors double-counted business earnings. | Reject aggregate ownership above 100%, with a small floating-point tolerance. |
| Arithmetic | A positive annual rate of `1e-16` divided by zero; overflow could crash or produce a decision. | Stable `log1p`/`expm1` amortization; reject non-finite calculated amounts with HTTP 422. |
| Zero debt service | Infinite coverage passed approval factors and serialized as null. | Emit an explicit not-applicable value with an unevaluated factor; it cannot satisfy approval. |
| Consumer documentation | `{income: true}` passed the documentation check despite absent asset/debt checks. | Require the configurable prototype checklist (`income`, `assets`, `debts`) in both evaluation paths. |
| Decision explanation | Exactly 43% DTI caused review with no recorded reason. | Store the review boundary as a zero-weight factor and derive its reason normally. |
| SBA inputs | Negative size measures were accepted; misspelled acquisition types silently used the expansion floor. | Validate input domains and enumerate supported transaction types. |
| Text extraction | Negative amounts disappeared; malformed commas changed values; multiple decimal points crashed; confirmed string `NaN` crossed the extraction boundary. | Parse signed/accounting-format numbers strictly and reject non-finite confirmed values. Preserve Windows line endings. |
| Workspace | Overriding gross receipts to $1 left APPROVE, ratios, and memo unchanged; uploads only changed a filename. | Calculate through the backend; use returned factors in coverage/memo; validate and load complete JSON requests. |
| Workspace failure states | Invalid numbers and blank rationales could enter the spread; no backend failure handling existed. | Validate edits, require a nonblank rationale, cancel stale requests, clear outdated results, and support retry. |

## Verification

- 53 backend tests pass (15 original, 38 added). On an isolated copy of the base commit, 37 added regression cases fail; the Windows-line-ending preservation check passes.
- Reference calculator: 18 numeric values and 2 flags pass; all 7 formula mutations are detected. The independent reference calculator is unchanged.
- 4 browser tests cover edits, coverage/memo/audit consistency, validation, API failure, and JSON import. Desktop and mobile screenshots inspected; no horizontal page overflow at 390px.
- TypeScript/Vite production build passes. `npm audit --audit-level=high` reports zero vulnerabilities for the locked frontend dependency graph.
- CI now uses `npm ci` and runs the browser regressions in addition to the original gates.

## Scope and remaining limits

This verifies deterministic prototype behavior, not suitability for real lending. Official SBA size rows remain intentionally absent and fail closed. SOP selection is explicit rather than date-driven. The UI supports complete commercial JSON requests; backend CSV/text helpers are not upload endpoints. Audit history remains in browser memory. No production authentication, durable storage, OCR, external data integration, regulatory validation, or predictive model validation was added.

The installed Starlette test client emits an upstream `httpx` deprecation warning; tests pass. Local browser tests used a separately installed Chromium because the standard browser download was unavailable in this environment. That environment workaround is not a project dependency.
