## Architecture and compatibility

The approved migration uses one financial boundary module and the existing
calculation graph. It adds no LLM, statistical model, finance library, OCR
service, speculative ratio, payment schedule or dependency abstraction.
LTV, debt yield, IRR/NPV and price/volume/mix bridges are absent from the actual
implementation and were not invented as new features. SR 11-7 simulation and
agentic-tool requirements do not describe this deterministic repository.

Canonical v2 financial JSON uses strings; integer counts/terms remain integers.
SQL schema contents and storage wrapper identities are unchanged. Frozen v1
fixture SQL/provenance were not modified. Reads and original retry receipts
retain original numeric JSON/hashes. New calculation, serialization, scenario
and fingerprint versions identify the changed financial semantics. Unsupported
old replay is never claimed to match.

The supported calculation context is 96 digits with HALF_EVEN and traps for
DivisionByZero, InvalidOperation, Overflow and Underflow. Input values are zero
or magnitude 1e-30 through 1e30 with at most 34 significant digits. Reporting
allocations do not change raw comparisons or accepted source input.
